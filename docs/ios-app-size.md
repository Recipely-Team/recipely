# iOS app size

Measured 2026-10-16 from an unsigned Release archive of `dev`
(`xcodebuild … -configuration Release -sdk iphoneos archive`), arm64.

## Why iOS looks bigger than Android

The two stores show different numbers. The App Store shows the **installed** size of the app.
Google Play shows the **compressed download** for one device's CPU and screen density. The same
build is about 58 MB installed and 19.5 MB compressed, so the listings differ by about 3× before
anything is wrong.

## What the 58 MB is

| Part | Size | Note |
|---|---|---|
| `Frameworks/` | 29 MB | React 11 MB, Hermes 4.8 MB, libavif 3.8 MB, ExpoModulesCore 3.7 MB, … |
| Main binary | 17 MB | Firebase, Google Mobile Ads, Google Sign-In; already stripped |
| `main.jsbundle` | 9.1 MB | already Hermes bytecode |
| Assets, lproj, share extension | ~2.5 MB | the extension is 208 KB |

## The one large saving

The precompiled Expo / React Native frameworks are embedded **with their debug symbols**. For
example, `React` carries 96 261 debug symbol entries and `hermesvm` 39 252. The main binary is
stripped; these frameworks are copied in as they come.

Running `strip -S -x` on each embedded framework binary (on a copy of the archive) gave:

| | Installed | Compressed |
|---|---|---|
| Now | 58 MB | 19.5 MB |
| Frameworks stripped | 45 MB (−13 MB, −22%) | 17.5 MB (−2 MB) |

Crash reports would not lose anything: the dSYMs are produced separately in the archive and are
what Crashlytics symbolicates with.

## How it would be done (not done)

`ios/` is generated by `expo prebuild`, so the change is an Expo config plugin in `app.json`.
It adds a Release-only build step that strips the embedded frameworks **before** they are code
signed (stripping after signing breaks the signature). This is a native build change: CLAUDE.md
asks before making one, and it needs a local Release build that launches, plus the Android build,
before merge.

Decision 2026-10-16: report only, no change yet.

## Smaller, harder options

- `libavif` (3.8 MB) is expo-image's AVIF decoder. The backend serves WebP and JPEG, but removing
  it means patching expo-image.
- Google Mobile Ads is a large part of the main binary; it is needed while ads ship.
